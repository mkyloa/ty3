# ty3 — переклад субтитрів EN→UK

Бере англійський `.srt` (або фільм у `.mkv`/`.mp4`) і віддає український переклад,
який знає, **хто говорить і до кого**: правильний рід, послідовна матриця «ти/Ви»,
кличний відмінок, офіційні імена й дотримання норм субтитрування. Тайминги
лишаються недоторканими.

```bash
ty3 translate movie.mkv
# → out/movie/final.uk.srt  +  qa-report.md
```

## Швидкий старт

**Потрібно:**

- Python ≥ 3.11
- Один із бекендів (див. [Бекенди](#бекенди)). Найпростіше — встановлений і
  залогінений [Claude Code](https://claude.com/claude-code): ключ API не потрібен.
- `ffmpeg` — лише якщо подаєте відеоконтейнер, а не `.srt`.

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"          # + ".[gemini]" для бекенда Gemini

.venv/bin/ty3 estimate movie.en.srt         # скільки викликів, без витрат
.venv/bin/ty3 translate movie.en.srt        # повний прогін
```

Відкрийте `out/movie/qa-report.md` — він каже, що варто перевірити людині
(див. [Що читати у QA-звіті](#що-читати-у-qa-звіті)).

## Як це працює

### Чому не «переклади рядок за рядком»

Українській потрібна інформація, якої в окремому рядку субтитрів **немає**:

| Що потрібно українській | Чого немає в SRT |
|---|---|
| `сказав` / `сказала` | хто говорить (стать мовця) |
| `ти` vs `Ви`, `тебе` vs `вас` | стосунки між мовцем і адресатом |
| `Джоне!`, `мамо`, `пані Сміт` | кличний відмінок, статус адресата |
| послідовні імена й терміни | глобальний контекст фільму |
| ≤42 симв./рядок, ≤17 CPS | тайминги є, але змінювати їх не можна |

Тому спершу будується «біблія перекладу», і лише потім перекладається текст —
уже з готовими рішеннями.

### Пайплайн

```
movie.en.srt
 ①  parse        cues[]: текст, тайминги, розмітка, тип реплики       [без API]
 ②  segment      сцени → чанки з контекстом ±5 реплик                 [без API]
 ③  research     dossier.json — каст, стать, офіційні імена, синопсис  ← вебпошук
 ④  speakers     speakers.json — мовець+стать+адресат для КОЖНОЇ реплики
 ⑤  bible        bible.json — матриця ти/Ви, глосарій, драбинка лайки
 ⑥  translate    переклад + самоперевірка за чеклістом в одному виклику на чанк
 ⑦  lint+fix     детерміновані перевірки → LLM лише для позначених реплик
 ⑧  fit          стиснення реплик, що не влазять у бюджет символів
 ⑨  render       final.uk.srt + qa-report.md                          [без API]
```

- **Переклад і редактура — один виклик на чанк.** Модель проходить чекліст
  редактора як самоперевірку перед відповіддю. На повнометражному фільмі
  (~28 чанків) ці два проходи були найдорожчими; об'єднання вдвічі скорочує
  кількість викликів за тієї ж перевірки.
- **Тайминги й індекси не змінюються ніколи.** Після запису файл звіряється з
  джерелом побайтово; розбіжність — помилка у звіті.
- **Кеш дає resume.** Відповіді кешуються за хешем у `out/<фільм>/.cache/`. Якщо
  прогін упав на 70-му виклику, повторний запуск продовжить звідти. Зміна промпта
  інвалідує лише залежні кроки.

## Бекенди

Пайплайн не прив'язаний до провайдера. Бекенд задається в `config.toml`
(`[model] backend`) або прапорцем `--backend`.

| Бекенд | Ключ | Встановлення |
|---|---|---|
| `claude-cli` (дефолт) | **не потрібен** — працює на підписці Claude Code | — |
| `gemini` | безкоштовний з [AI Studio](https://aistudio.google.com/apikey) → `GEMINI_API_KEY` | `pip install -e ".[gemini]"` |
| `anthropic` | платний `ANTHROPIC_API_KEY` | — |

Ключі кладіть у `.env` (шаблон — `.env.example`). Усі три бекенди підтримують
структурований вивід і вебпошук для проходу research.

| | `claude-cli` | `gemini` | `anthropic` |
|---|---|---|---|
| Накладні витрати на виклик | ~6 тис. токенів (без мінімізації було б ~26 тис.) | немає | немає |
| Контекст | — | 1M | 1M |
| Явний кеш промптів (`ttl: 1h`) | — | — | так |
| Вартість у `run.log` | так | лише токени | лише токени |
| Нюанси | витрачає ліміти підписки | якість української варто перевірити на своєму матеріалі | **не перевірений живими викликами** |

Модель за замовчуванням — `claude-opus-5-5` (для `gemini` — `gemini-2.5-pro`).
Змінюється в `config.toml` або `--model`. Перед першим серйозним прогоном на
`anthropic` зробіть `ty3 estimate` і прогоніть короткий файл.

## Команди

```bash
ty3 translate movie.en.srt                    # повний прогін
ty3 translate movie.en.srt --context notes.md # + синопсис, офіційні імена, каст зі статтю
ty3 translate movie.en.srt --review           # пауза на перевірку досьє й біблії
ty3 research  movie.en.srt                    # лише зібрати контекст фільму
ty3 estimate  movie.en.srt                    # оцінити обсяг без витрат
ty3 check     movie.en.srt movie.uk.srt --bible out/movie/bible.json  # лінтери
```

Корисні прапорці `translate`:

| Прапорець | Що робить |
|---|---|
| `--jobs N` | паралель по сценах — швидше, але гірша зв'язність |
| `--effort low\|medium\|high\|xhigh\|max` | глибина міркувань моделі |
| `--bilingual` | двомовний файл для рецензування |
| `--dossier FILE` / `--bible FILE` | підкласти виправлені руками |
| `--no-cache` | ігнорувати кеш відповідей |

Повний список — `ty3 <команда> --help`.

## Субтитри з MKV та інших контейнерів

`.mkv`, `.mp4`, `.webm`, `.mov`, `.ts` приймаються напряму. Субтитри витягаються
через ffmpeg у `out/<фільм>/source.en.srt`, і повторний прогін бере вже витягнутий
файл (щоб витягти заново, видаліть його).

```bash
ty3 tracks movie.mkv                  # які дорожки є і яка буде вибрана
ty3 extract movie.mkv                 # лише витягти, без перекладу
ty3 translate movie.mkv --pick-track  # вибрати дорожку вручну зі списку
```

### Як вибирається дорожка

Помилка тут дорога: forced-дорожка містить лише чужомовні репліки, і замість
1500 реплик ви перекладете 40. Тому дорожки ранжуються:

| Ознака | Вплив |
|---|---|
| Мова збігається з `--sub-language` (типово `eng`) | сильний плюс |
| Інша мова | сильний мінус |
| `forced` (за флагом або назвою: Forced, Signs, Songs) | сильний мінус |
| SDH / hearing impaired | невеликий мінус — придатна, але з описами звуків |
| Більше реплик (`NUMBER_OF_FRAMES`) | плюс |
| `subrip` замість `ass` | невеликий плюс — без конвертації |

Перевизначення: `--pick-track`, `--track N` (номер із `ty3 tracks`; бʼє
`--pick-track`), `--sub-language ukr`, `--allow-forced`.

`--pick-track` **не вішає неінтерактивні запуски**: якщо stdin не термінал (фон,
CI, конвеєр), береться рекомендована дорожка.

### Формати

- **ASS/SSA, WebVTT** конвертуються в SRT автоматично (складна стилізація спрощується).
- **PGS (Blu-ray), VobSub (DVD), DVB** — це зображення, а не текст. Буде зрозуміла
  помилка з переліком знайденого, а не порожній файл. Обхід: окремий `.srt` або
  OCR (напр. Subtitle Edit).

### Скільки це триває

ffmpeg мусить прочитати контейнер **цілком**: субтитрові пакети розкидані по всьому
файлу. Час залежить від розміру файлу й швидкості носія, а не від тривалості фільму.
Заміряно: **7.6 ГБ на зовнішньому диску 16 МБ/с ≈ 8 хвилин.** Прогрес виводиться
у відсотках, а ліміт часу обчислюється з розміру файлу. Для дуже повільних
носіїв або мережевих шар:

```toml
[media]
extract_timeout_s = 3600   # 0 = обчислити з розміру
slow_media_mb_s = 3.0      # нижня оцінка швидкості носія, МБ/с
```

## Результати прогону

```
out/<фільм>/
  source.en.srt    витягнуте з контейнера (лише коли вхід — .mkv тощо)
  dossier.json     каст, стать персонажів, офіційні імена, синопсис
  speakers.json    мовець і адресат для кожної реплики
  bible.json/.md   матриця ти/Ви, глосарій, голоси, драбинка інвективи
  draft.srt        переклад до редактури — для порівняння
  final.uk.srt     результат
  bilingual.srt    UA + EN курсивом (з --bilingual)
  qa-report.md     що перевірити людині
  run.log          JSONL: usage і вартість кожного виклику
  .cache/          відповіді за хешем — повторний запуск не платить двічі
```

### Що читати у QA-звіті

Звіт існує, щоб не читати 1500 реплик підряд. Порядок:

1. **Пропущено**: якщо не нуль, частина реплик не перекладена.
2. **Відкриті питання**: де модель не змогла вирішити сама.
3. **Персонажі з невизначеною статтю**: там рід обходився конструкціями без роду.
4. **Прапорці** `wordplay_lost` (втрачена гра слів), `too_long` (не влізло).
5. **Помилки лінтера, що лишилися**: порушення норм або матриці ти/Ви.
6. **Найчастіші причини правок редактора** підказують, що додати в
   `prompts/uk_rules.md` перед наступним фільмом.

### Ручна перевірка

```bash
# тайминги мусять бути тотожні джерелу: вивід має бути порожній
diff <(grep -oE '^[0-9:,]+ --> .*' movie.en.srt) \
     <(grep -oE '^[0-9:,]+ --> .*' out/movie/final.uk.srt)

# подивитися з відео
ffplay -vf "subtitles=out/movie/final.uk.srt" movie.mp4
```

## Де живе якість

Не в коді, а в `src/ty3/prompts/`. Це звичайні текстові файли, які правляться без
зміни коду, і саме сюди осідають висновки з рецензій готових фільмів.

| Файл | Що в ньому |
|---|---|
| `uk_rules.md` | рід, ти/Ви, кличний відмінок, транслітерація, інвектива, правопис-2019 |
| `en_uk_traps.md` | канонічні відповідники для `Look,`, `I mean`, `Fine.`, `Come on!`: на них машинний переклад видає себе |
| `subtitle_norms.md` | норми субтитрування, порядок скорочення, розрив рядка |
| `russianisms.tsv` | русизми → заміни (використовують і лінтер, і промпт) |
| `system_*.md` | роль для кожного проходу |

Числові норми (символів на рядок, CPS, тривалість) лежать у `config.toml`, секція
`[subtitle]`. За замовчуванням стоїть стиль Netflix UK-ua.

## Тести

```bash
.venv/bin/python -m pytest -q
```

Тести не звертаються до API, тож прогін швидкий і безкоштовний. Вони покривають
парсер і рендер (round-trip, збереження таймінгів), сегментацію, лінтери, кеш і
ретраї, побудову команди CLI-бекенда, мапінг Gemini, звіт і витягання субтитрів.
Тести MKV збирають справжній контейнер через ffmpeg і пропускаються, якщо ffmpeg
немає. Тести Gemini пропускаються, якщо не встановлено `.[gemini]`.

## Обмеження

- **Часткова розмітка** (`He said <i>maybe</i> tomorrow`) після перекладу не може
  бути позиційно точною. Курсив застосовується до всього рядка, і це позначається у звіті.
- **Маловідомі фільми.** Research спирається на веб, і офіційних українських імен
  може не існувати. Тоді буде транслітерація з прапорцем `name_unofficial`, але
  краще передати імена через `--context`.
- **Prompt injection.** Вміст вебсторінок трактується як дані, а не інструкції.
  Досьє все одно варто переглянути перед прогоном: для цього є `--review` і `--dossier`.
- **Batch API не реалізовано.** Прапорець `[run] batch` у `config.toml` поки ні на
  що не впливає.
- **Повільне витягання з MKV.** `mkvextract` (mkvtoolnix) читає лише потрібну
  дорожку через індекс Matroska і на 7.6 ГБ працював би секунди замість хвилин.
  Поки не реалізовано.
