# ty3 — переклад субтитрів EN→UK

Отримує англійський `.srt`, віддає український — із контекстом персонажів,
узгодженим родом, матрицею «ти/Ви» та дотриманням норм субтитрування.

```bash
ty3 translate movie.en.srt      # або одразу з контейнера:
ty3 translate movie.mkv
# → out/movie/final.uk.srt  +  qa-report.md
```

## Чому не «переклади рядок за рядком»

Українська вимагає інформації, якої в окремому рядку субтитрів **немає**:

| Що потрібно українській | Чого немає в SRT |
|---|---|
| `сказав` / `сказала` | хто говорить (стать мовця) |
| `ти` vs `Ви`, `тебе` vs `вас` | стосунки між мовцем і адресатом |
| `Джоне!`, `мамо`, `пані Сміт` | кличний відмінок, статус адресата |
| послідовні імена й терміни | глобальний контекст фільму |
| ≤42 симв./рядок, ≤17 CPS | тайминги є, але змінювати їх не можна |

Тому це багатопрохідний пайплайн: спершу будується «біблія перекладу», і лише
потім перекладається текст — уже з готовими рішеннями.

## Пайплайн

```
movie.en.srt
 ①  parse        cues[]: текст, тайминги, розмітка, тип реплики       [без API]
 ②  segment      сцени → чанки з контекстом ±5 реплик                 [без API]
 ③  research     dossier.json — каст, стать, офіційні імена, синопсис  ← вебпошук
 ④  speakers     speakers.json — мовець+стать+адресат для КОЖНОЇ реплики
 ⑤  bible        bible.json — матриця ти/Ви, глосарій, драбинка лайки
 ⑥  translate    переклад + самоперевірка за чеклістом в одному виклику на чанк
 ⑦  lint+fix     детерміновані перевірки → LLM лише для позначених реплик
 ⑧  fit          стиснення реплик, що не влазять у бюджет символів
 ⑨  render       final.uk.srt + qa-report.md                          [без API]
```

Переклад і редактура — **один виклик на чанк**, не два. Модель проходить чекліст
редактора як самоперевірку перед відповіддю, а не в окремому виклику над готовим
текстом. Причина економічна: на повнометражному фільмі (~28 чанків) саме ці два
проходи були найдорожчою статтею витрат у всьому пайплайні — об'єднання вдвічі
скорочує кількість викликів тут, лишаючи ту саму перевірку.

**Тайминги й індекси не змінюються ніколи.** Це перевіряється побайтово після
запису файлу; розбіжність — помилка, що йде у звіт.

## Встановлення

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
```

## Бекенди — ключ Anthropic не обов'язковий

Пайплайн не привʼязаний до провайдера. Бекенд задається в `config.toml` або `--backend`.

| Бекенд | Ключ | Як вибрати |
|---|---|---|
| `claude-cli` (дефолт) | **не потрібен** — працює на підписці Claude Code | `--backend claude-cli` |
| `gemini` | безкоштовний з [AI Studio](https://aistudio.google.com/apikey) → `GEMINI_API_KEY` | `--backend gemini` |
| `anthropic` | платний `ANTHROPIC_API_KEY` | `--backend anthropic` |

Обидва безключові бекенди підтримують і структурований вивід, і вебпошук для
проходу research, тож якість не деградує.

Особливості, які варто знати:

- **`claude-cli`** додає ~6 тис. токенів накладних витрат на виклик (адаптер уже
  мінімізує їх, замінюючи системний промпт і вимикаючи інструменти — без цього
  було б ~26 тис.). Витрачає ліміти підписки. Немає Batch API.
- **`gemini`** без накладних витрат, 1M контексту, `response_schema` приймає
  pydantic напряму. Якість українського варто перевірити на своєму матеріалі.
- **`anthropic`** єдиний із повним контролем кешу промптів (`ttl: 1h`) і Batch API
  (−50%), тому найдешевший на повнометражних фільмах. Не перевірений живими
  викликами — у проєкті немає ключа.

## Субтитри з MKV та інших контейнерів

`.mkv`, `.mp4`, `.webm`, `.mov`, `.ts` приймаються напряму — субтитри витягаються
через ffmpeg і лягають у теку виводу як `source.en.srt`, щоб було видно, що саме
перекладалося.

```bash
ty3 tracks movie.mkv                  # які дорожки є і яка буде вибрана
ty3 extract movie.mkv                 # лише витягти, без перекладу
ty3 translate movie.mkv               # витягти й перекласти
ty3 translate movie.mkv --pick-track  # вибрати дорожку вручну зі списку
```

`--pick-track` показує список і питає номер; Enter бере рекомендовану, `q` скасовує.
Це прибирає два кроки — не потрібно спершу дивитися `tracks`, потім перезапускати
з `--track N`. Ручний вибір бʼє евристику: forced-дорожку можна взяти свідомо.

Інтерактив **не є поведінкою за замовчуванням і не вішає неінтерактивні запуски**:
якщо stdin не термінал (фон, CI, конвеєр), виводиться список і береться
рекомендована дорожка, а не очікування вводу, якого ніхто не дасть.

**Дорожку вибирає не «перша-ліпша».** У релізі їх зазвичай кілька, і помилка тут
дорога: forced-дорожка містить лише чужомовні репліки — перекласти її замість
повної означає отримати 40 реплик замість 1500. Правила вибору:

| Ознака | Вплив |
|---|---|
| Мова збігається з `--sub-language` (типово `eng`) | сильний плюс |
| Інша мова | сильний мінус |
| `forced` (за флагом або назвою: Forced, Signs, Songs) | сильний мінус |
| SDH / hearing impaired | невеликий мінус — придатна, але з описами звуків |
| Більше реплик (`NUMBER_OF_FRAMES`) | плюс |
| `subrip` замість `ass` | невеликий плюс — без конвертації |

Перевизначення: `--pick-track` (вибрати зі списку), `--track N` (номер із
`ty3 tracks`), `--sub-language ukr`, `--allow-forced`. Явний `--track N` бʼє
`--pick-track`: якщо номер уже названий, питати вдруге немає сенсу.

**Растрові субтитри не підтримуються — і це явна помилка, не тиха.** PGS (Blu-ray),
VobSub (DVD) і DVB — це зображення, а не текст; без OCR із них нічого не дістати.
Такий контейнер дає зрозуміле повідомлення з переліком знайденого, а не порожній
файл. Обхід: узяти окремий `.srt` або прогнати файл через OCR (напр. Subtitle Edit).

ASS/SSA і WebVTT конвертуються в SRT автоматично; складна стилізація при цьому
спрощується — для перекладу це доречно.

### Скільки це триває

ffmpeg мусить прочитати контейнер **цілком**: субтитрові пакети розкидані по всій
довжині фільму, тож пропустити відеодані не можна. Тому час залежить не від
тривалості фільму, а від розміру файлу й швидкості носія.

Заміряно на реальному Blu-ray: **7.6 ГБ на зовнішньому диску 16 МБ/с ≈ 8 хвилин**.

Ліміт часу тому обчислюється з розміру файлу, а не є константою (константа завжди
буде або замалою для великого файлу на повільному диску, або безглуздо великою для
маленького). Прогрес виводиться у відсотках — інакше процес неможливо відрізнити
від зависання.

Витягнутий `source.en.srt` **не витягається вдруге**: повторний `translate` того
самого фільму бере готовий файл. Щоб витягти заново — видаліть його.

Якщо ліміту все одно бракує (дуже повільний носій, мережева шара):

```toml
[media]
extract_timeout_s = 3600   # у секундах; 0 = обчислити з розміру
slow_media_mb_s = 3.0      # нижня оцінка швидкості носія
```

**Швидша альтернатива для MKV:** `mkvextract` із mkvtoolnix читає лише потрібну
дорожку через індекс Matroska, не проходячи весь файл. На 7.6 ГБ це різниця між
хвилинами й секундами. Поки не реалізовано — див. розділ «Обмеження».

## Команди

```bash
# Повний прогін
ty3 translate movie.en.srt

# Із додатковим контекстом (синопсис, офіційні імена, каст зі статтю)
ty3 translate movie.en.srt --context notes.md

# З паузами на перевірку досьє та біблії перед перекладом
ty3 translate movie.en.srt --review

# Лише знайти контекст фільму
ty3 research movie.en.srt

# Оцінити обсяг без витрат
ty3 estimate movie.en.srt

# Прогнати лінтери на готовому перекладі
ty3 check movie.en.srt movie.uk.srt --bible out/movie/bible.json
```

Корисні прапорці: `--jobs N` (паралель по сценах — швидше, гірша зв'язність),
`--effort low|medium|high|xhigh|max`, `--bilingual` (двомовний файл для рецензування),
`--dossier` / `--bible` (підкласти виправлені руками), `--no-cache`.

## Артефакти прогону

```
out/<фільм>/
  source.en.srt    витягнуте з контейнера (лише коли вхід — .mkv тощо)
  dossier.json     каст, стать персонажів, офіційні імена, синопсис
  speakers.json    мовець і адресат для кожної реплики
  bible.json/.md   матриця ти/Ви, глосарій, голоси, драбинка інвективи
  draft.srt        переклад до редактури — для порівняння
  final.uk.srt     результат
  bilingual.srt    UA + EN курсивом (з --bilingual)
  qa-report.md     що перевірити людині
  run.log          JSONL: usage і вартість кожного виклику
  .cache/          відповіді за хешем — повторний запуск не платить двічі
```

**Кеш дає resume.** Якщо прогін упав на 70-му виклику, повторний запуск
продовжить із того місця. Зміна промпта інвалідує лише залежні кроки.

## Що читати у QA-звіті

Звіт існує, щоб не читати 1500 реплик підряд. Дивись у такому порядку:

1. **Пропущено** — якщо не нуль, частина реплик не перекладена.
2. **Відкриті питання** — де модель не змогла вирішити сама.
3. **Персонажі з невизначеною статтю** — там рід обходився конструкціями без роду.
4. **Прапорці**: `wordplay_lost` (втрачена гра слів), `too_long` (не влізло).
5. **Помилки лінтера, що лишилися** — порушення норм або матриці ти/Ви.
6. **Найчастіші причини правок редактора** — це підказка, що додати в
   `prompts/uk_rules.md` перед наступним фільмом.

## Де живе якість

Не в коді, а в `src/ty3/prompts/`:

| Файл | Що в ньому |
|---|---|
| `uk_rules.md` | рід, ти/Ви, кличний відмінок, транслітерація, інвектива, правопис-2019 |
| `en_uk_traps.md` | канонічні відповідники для `Look,`, `I mean`, `Fine.`, `Come on!` — того, на чому машинний переклад видає себе |
| `subtitle_norms.md` | норми субтитрування, порядок скорочення, розрив рядка |
| `russianisms.tsv` | русизми → заміни (використовує й лінтер, і промпт) |
| `system_*.md` | роль для кожного проходу |

Це звичайні текстові файли: правиш без зміни коду. **Саме тут осідають висновки
з рецензій готових фільмів** — так якість зростає між прогонами.

## Тести

```bash
.venv/bin/python -m pytest -q     # 242 тести, без API — швидко й безкоштовно
```

Покривають парсер/рендер (round-trip і збереження таймінгів), сегментацію,
лінтери, кеш і ретраї Runner, побудову команди CLI-бекенда, серіалізацію
контексту, звіт і витягання субтитрів. Тести MKV збирають справжній контейнер
через ffmpeg і пропускаються, якщо ffmpeg немає.

Перевірка після реального прогону:

```bash
# тайминги мусять бути тотожні джерелу — вивід має бути порожній
diff <(grep -oE '^[0-9:,]+ --> .*' movie.en.srt) \
     <(grep -oE '^[0-9:,]+ --> .*' out/movie/final.uk.srt)

# норми та матриця ти/Ви
ty3 check movie.en.srt out/movie/final.uk.srt --bible out/movie/bible.json

# візуально
ffplay -vf "subtitles=out/movie/final.uk.srt" movie.mp4
```

## Обмеження, про які варто знати

- Часткова розмітка (`He said <i>maybe</i> tomorrow`) після перекладу не може бути
  позиційно точною — курсив застосовується до всього рядка, факт позначається.
- Прохід research спирається на веб: для маловідомих фільмів офіційних
  українських імен може не існувати. Тоді транслітерація + флаг `name_unofficial`;
  краще передати їх через `--context`.
- Вміст веб-сторінок трактується як **дані, не інструкції** (захист від
  prompt injection), але досьє все одно варто переглянути перед прогоном — для
  цього є `--review` і `--dossier`.
